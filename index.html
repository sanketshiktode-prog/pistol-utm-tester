Set up once

  1. Developer token — MCC → Admin → API Center. Paste it into ADS.devToken in apps-script-ads-api.gs. A new token has Test access, which works only against test accounts — right for the trial, and the reason to trial on one.
  2. A test manager account — a test account cannot live under your production MCC; Google keeps the two hierarchies apart. Open Google's test account page and press Create a test manager account, signing in with a Google account that is not linked to the production MCC. Then, inside it, Accounts → Create new account — every client created there is automatically a test account.
  3. Point the script at it — while trialling, ADS.loginCid is the test manager ID, not the production MCC. The Customer ID box takes the test client ID. Give the Google account that deployed the script access to the test manager, or it cannot reach it. Switch ADS.loginCid back to the production MCC once Basic access is approved.
  4. The adwords scope — in the Apps Script, Project Settings → show appsscript.json, add https://www.googleapis.com/auth/adwords to oauthScopes, then run adsSelfTest() once from the editor and accept the permission prompt. Skip this and every call returns 401.
  5. Redeploy — Deploy → Manage deployments → pencil → Version: New version → Deploy.
  6. Production access — a real account needs Basic access, applied for in the Cloud console after brand verification. Test access cannot touch it.
